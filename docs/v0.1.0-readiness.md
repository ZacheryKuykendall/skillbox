## What the fresh clone caught

The fresh-clone verification found a real defect that the working repository could not have surfaced.

The repository was initialized with `git config core.autocrlf false`. Every gate passed locally because of that setting. A clean clone on Windows with the common default of `core.autocrlf=true` failed three ways:

1. `pnpm format:check` reported style issues in **193 files**, because Prettier is configured `endOfLine: "lf"`.
2. The JSON Schema drift test failed, comparing LF-generated bytes against a CRLF checkout.
3. The example project reported **every installed file as modified**, because a file checked out with CRLF hashes differently from the same file with LF.

The third is the serious one: it would have made `skillbox doctor` useless for every Windows user, and it directly undermines the integrity guarantee in [ADR-0004](architecture/decisions/ADR-0004-lockfile-design.md).

Fixed by committing a `.gitattributes` with `* text=auto eol=lf`. Unlike `core.autocrlf`, it travels with the repository and so applies to every clone regardless of a contributor's global configuration. ADR-0004 now records line-ending normalization as part of the determinism decision rather than an incidental setting.

Re-verified after the fix: all seven gates pass on a clean clone.

This is the argument for the criterion existing. Reasoning about it would not have found it; only running it did.

## What the first CI run caught

The same lesson repeated once CI ran on GitHub. Every substantive gate passed on the first run — install, format, lint, typecheck, build, tests with coverage, catalog validation, schema generation — and only the working-tree drift check failed. It was right to.

**Nine files were stored in the index with CRLF.** `git ls-files --eol` reported `i/crlf` for `.cursor/rules/*.mdc`, `.editorconfig`, `.gitignore`, `.npmrc`, `.prettierignore`, `LICENSE`, and `.github/CODEOWNERS`. Every one is a file Prettier does not process, so `pnpm format` never rewrote it to LF the way it did everything else. Once `.gitattributes` declared `eol=lf`, git wanted LF in the index, so these appeared modified on every clone. Fixed with `git add --renormalize .`, verified line-endings-only.

**`pnpm-lock.yaml` was stale.** It had no `examples/starter-project` importer, because that workspace member was added in Phase 7 after the last `pnpm install`.

Note the shape: this is the _second_ line-ending defect, after the fresh-clone one above, and both had the same cause — a file outside Prettier's reach keeps CRLF and nothing notices until a clean environment compares it. The fresh-clone check caught the checkout side; CI caught the index side. Neither would have found the other.

The drift check's own error message was also misleading, advising `pnpm schema:generate` for any dirty file, which sent the first diagnosis toward `schemas/`. It now names all three likely causes.

CI is now green on all three matrix legs, and the actions have been moved off the deprecated Node 20 runtime that the first green run warned about.

## Known limitations

Stated plainly, because a readiness report that lists only successes is not useful.

- **The catalog is local to this repository.** There is no remote registry, no publishing, and no package signing. This is the central limitation of v0.1.0 ([ADR-0003](architecture/decisions/ADR-0003-local-registry-first.md)).
- **Permissions are declared, not enforced.** Skillbox has no runtime to enforce them in. They are validated and displayed so a user can decide. Enforcement requires sandboxed execution (SBX-119).
- **No execution.** `script` resources are installed but never run by Skillbox. This is a deliberate guarantee, not a gap.
- **`v1alpha1` is unstable.** The manifest format may change before v1.
- **A tampered file with a correctly-updated digest is undetectable** by digest alone. Requires signing (SBX-111).
- **"Require review from Code Owners" is off.** `.github/CODEOWNERS` assigns ownership to `@ZacheryKuykendall`, but the branch protection requirement is deliberately not enabled: with a single code owner it would make every pull request unmergeable, because GitHub never requests a review from the author and nobody can approve their own. Review is advisory until a second maintainer exists (SBX-018).
- ~~The CI workflow has not yet completed a run on GitHub.~~ **Resolved.** CI is green on all three matrix legs — Linux and Windows on Node 24, plus Linux on Node 20.19. The first run also proved the workflow can fail, catching two real defects (see below).
- **Namespace ownership is unenforced.** Any contributor can use any namespace. Acceptable under pull-request review; a real problem once publishing exists (SBX-104).

All fourteen acceptance criteria are met, with executed-command evidence for each.

Skillbox v0.1.0 is ready. A developer can clone the repository, install, run every gate, initialize a project, search the catalog, inspect a resource, install it, see it recorded in both the manifest and the lockfile, validate the project, remove it safely, and follow documentation to create and contribute their own resource — with one working example of every supported kind to read, and a documented security model to consult first.
